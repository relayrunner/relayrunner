Hosted providers run GitHub Actions jobs on their own machines, under your account with them. RelayRunner can send jobs to any of these when your own machines are busy, or ahead of GitHub-hosted runners.

## Set it up

1. Install the provider's GitHub App on the organization and set up your account with them. RelayRunner only hands the job one of the provider's labels; the provider's App runs it and bills you.
2. Add the provider to your workspace's [runner order](/docs/concepts/runner-order) on the Router page.
3. Name one of its labels in the relay input of the same name:

```yaml
relay-test:
  uses: relayrunner/actions/.github/workflows/relay.yml@v1
  with:
    machine: self-hosted
    depot: depot-ubuntu-24.04
    github: ubuntu-latest
```

`relayrunner init` keeps a job's existing provider label as its fallback, so a job already on a hosted provider stays there whenever no machine is free.

## Where it sits in the order

A provider's step always takes a job that names one of its labels. RelayRunner can't see a provider's capacity, so steps below it only run for jobs that don't name one. A common order is your machines, then a hosted provider, then GitHub-hosted.

Unlike machines, hosted providers also run public repos' jobs.

RunsOn's label carries the run's id, so write it as an expression: `runs-on: runs-on=${{ github.run_id }}/runner=2cpu-linux-x64`.

## Good to know

- Provider-only actions in a job, such as Blacksmith's cache actions, won't work on your machines or GitHub. `init` warns about Blacksmith's.
