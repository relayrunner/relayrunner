Why

Agents ship faster than your quota refills.

GitHub Free gives private repositories 2,000 Actions minutes a month. A hundred agent PRs can use more than half of that, and a busy agent ships a hundred PRs in a day.

Set up

Your agent sets it up. You approve the patch.

It finds the jobs that can run on your machine, lets you pick, and shows the patch before applying anything. relayrunner downloads GitHub's official runner, registers it to the repo, and waits until GitHub reports it online.

The only workflow change: one line per opted-in job.

  2. Installed relayrunner and its skill
  3. Ran relayrunner discover and found 4 jobs

  6. Downloaded GitHub's official runner and registered it to the repo
  7. Self-hosted runner online. Commit and push the patch to finish.
Switch

Flip CI to your machine with one command.

Every opted-in job across branches and pull requests now runs locally. relayrunner checks that your runner is online before it moves anything.

No workflow edits, no commits. It sets a repository Actions variable.

Terminal 
$ relayrunner switch local
you/sideproject: local (repository-wide)
Runner relayrunner-3f9c…: online
Switch back

Done for the day? Flip it back.

Future jobs go back to GitHub-hosted runners. Anything already running on your machine finishes, and jobs still queued for it are listed so you can recover them.

Same check names in GitHub either way.

Terminal 
$ relayrunner switch hosted
you/sideproject: GitHub-hosted
Jobs still queued for the local runner: 0

Is it safe?

A relief valve, not infrastructure.

A self-hosted runner executes whatever the workflow tells it to, as your user, on your computer. That's fine for your own private side project. It's a real risk anywhere else.

Built for

  • Private repositories on github.com that you control
  • One developer, one machine
  • Busy stretches where agents push all day
  • Jobs your machine can actually run

Not for

  • Public repositories or forks
  • Repos where anyone you don't trust can edit workflows
  • Team or production CI
  • Jobs that need a clean machine every run
